# 逐卷写作的正文与规划自动修订

当前未保存正文、篇章规划、场景规划或章计划经一致性检查发现有原文引证的冲突时，逐卷队列自动执行：

1. 保留当前候选和冲突报告，将实际读取的前文、规划、资料与具体引证交给模型。
2. 只修订当前候选，保持原资料依据、位置和确认键；不修改已保存章节或规划。层级规划修订使用原任务的严格结果类型，同时禁止增删候选、改变名称和顺序、调整目标字数与章节预算、变更实体引用；仅修正必要的摘要和规划叙述。
3. 以独立请求重新运行原一致性检查。复核请求只接收修订后的候选和原始资料，不接收修订模型的结论。
4. 通过后，沿用原事务保存正文、不可变历史版本和审核报告，再执行章后事实闭环并推进下一章。

每个候选最多完成两次修订。两次后仍有冲突，任务以 `VOLUME_WRITING_CONSISTENCY_CONFLICT` 停在当前步骤，不正式采用候选。日志保留各次冲突、修订候选和复核结果；已保存内容不受影响。作者可查看日志、处理冲突后结束本轮并重新生成。达到上限后反复点继续不会重置修订次数。

修订记录持久化在任务的 `pending.consistency_repairs` 中，包括修订前候选与报告、修订后候选与报告、时间及模型用量。正文采用成功时，同一事务将这些记录归档到 `volume_writing_reports`。旧任务已有的 `pending.result` 和失败 `pending.review` 可以直接进入修订，无需先废弃本轮。

暂停、超时、重启后复用已完成步骤：修订返回的完整正文先保存检查点，再处理暂停请求；若复核失败或中断，继续时只重新复核；尚未返回结果的修订请求重新执行当前次数，不消耗下一次修订名额。修订请求也有 5 分钟总时限，暂停或结束的等待宽限为 15 秒。

完整逐卷任务采用规划时，同一事务在 `volume_writing_preparation_reports` 中归档修订前后候选与审核记录。已有失败任务的缓存场景或章计划可以直接进入修订，无需先废弃本轮。

章计划的 `pov_character_id` 原为 `null` 时，可按审核要求补填本次 `context.selected_entities` 中已读取且同时存在于冻结 `basis.source_refs` 的角色。该例外仅用于补齐空视角，已有非空视角不能更换或清空；候选数量、名称、顺序、预算和其他引用仍按原规则保护。修订器和采用前的队列校验都执行相同限制，补填后仍独立复核，保留原候选、来源和修订历史。旧任务中未完成的修订请求可直接继续，不重新生成章计划。

卷和篇章详细剧情、卷实体准备的冲突仍保留候选等待作者处理。无有效引证、返回无效结果、修订越过规划保护范围、资料过大或原数据版本发生变化时，不绕过原有校验。人工同时修改内容仍由原版本和来源保护拒绝覆盖。

验证：`python -m unittest scripts.test_volume_consistency_repair scripts.test_model_wait scripts.test_volume_continuation -v`。数据库集成测试创建并清理独立的随机测试库，不使用正式小说数据。
