# 逐卷写作自动补全规划

新任务默认 `complete_planning=true`。处理范围是当前卷，按篇章和场景顺序推进：

1. 缺少卷详细剧情时生成并保存，保留既定规划约束与预算。
2. 依次准备本卷势力、角色和地点；已有参与资料通过审核后复用，缺少时调用原卷资料流程。
3. 没有篇章时生成篇章规划。
4. 逐篇章补缺少的详细剧情；已有剧情来源失效时停止并提示核对，不自动覆盖。
5. 没有场景的篇章生成并保存场景；已有场景保持不变。
6. 沿用原逐场景队列补章计划、写正文、独立审校、事务保存以及章后事实闭环，再进入下一篇章。

既有部分场景不会仅凭章节目标自动追加场景，也不会按全卷目标重新生成一整套内容。生成器和确认服务沿用原父级剩余预算校验，队列额外检查已保存规划和已有章节是否超过预算。目标章数属于规划约束，不能用来覆盖已有剧情或正文。

## 保存与恢复

任务固定所有可能使用的默认流程修订。每次准备或规划的候选、审核以及生成节点检查点会先保存；采用时，在同一个 MongoDB 事务中保存正式内容、`volume_writing_preparation_reports` 审核记录、新目录指纹、范围统计和下一检查点。保存响应丢失后直接复用已经提交的进度，不重复创建篇章、场景或章计划。

心跳与准备结果采用共用检查点锁，避免自身状态更新导致事务写冲突。若暂停请求等并发更新造成明确已中止的写冲突，最多尝试三次；不重试提交结果不确定或一般网络错误，候选保留后等待原任务续跑。

目录指纹包含本卷、篇章、场景和章计划的实际规划内容，忽略正文写入及统计变化。只有本任务采用成功的结构变化可更新本轮范围；外部修改仍导致安全停止。剧情和正文采用继续使用原来源指纹、幂等键和版本保护。已有卷参与资料的版本在采用事务中再次核对。

原任务缺少 `settings.complete_planning` 时按 `false` 处理，目录指纹算法、生成范围及正文修订续跑均沿用旧行为。新请求显式设置 `false` 也可保留原行为。无需迁移既有任务或小说数据。

## 界面与验证

篇章规划页和章节编辑页都可打开逐卷写作。空场景列表允许开始新完整任务；面板显示缺详细剧情、尚无场景的篇章数量和篇章进度，旧任务明确标注原范围。

测试：`python -m unittest scripts.test_volume_preparation scripts.test_volume_continuation -v`。集成测试使用独立随机数据库，覆盖空卷完整生成、后续空篇章、已有内容保留、重复开始、暂停续跑、提交响应丢失和外部修改阻断。
