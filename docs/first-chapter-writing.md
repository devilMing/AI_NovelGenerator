# 一键写作到第一章

小说信息页右上角的“一键写作”会复用已保存内容，依次补齐核心势力、主角、可选关系/规则/物品、卷骨架、首卷剧情、卷内资料、首篇章剧情、场景、首章计划及正文。执行范围止于第一个活动父链中的首章，不是任意后卷已写章节。

核心势力、核心角色、世界规则、物品数量由 AI 按剧情需要决定（保留接口数量上限，不要求凑满），一键任务显式传入空数量，不继承自定义方案的固定数量。手动生成的内置默认方案同样默认自动数量，仍可切换为固定数量。

首章完成后保留“查看第一章”和“继续一键写作”两个入口。继续入口先以只读请求定位同书未结束的逐卷任务（含暂停/失败），没有原任务时定位首章所属卷，再打开原有逐卷面板核对范围；不会自动重跑首章或仅因打开面板就生成。作者确认开始/继续后，按该卷已保存场景补缺；已有章计划保留，已有非空正文跳过。尚未规划的篇章/场景不自动展开，不能将本轮范围等同于全卷或全书预算。

逐卷的章计划和正文在正式确认前复用独立、有原文引证约束的一致性审校。候选与通过的审校持久化，暂停或审核网络失败后可继续，不重复请求已有候选；明确内容冲突则阻止保存并在日志保留报告。新正文、历史修订与绑定该修订 hash 的审校记录在同一 MongoDB 事务内提交。业务确认继续使用原有来源校验、版本与幂等回执，作者并发保存的正文不会被覆盖。

逐卷写作在每章正文保存后自动执行“提取章后事实 → 确定性校验 → 独立 AI 审核 → 更新事实账本”，完成后才进入下一章。继续一键写作遇到已有正文时，不重写正文，而是先为该正文的当前不可变修订补建事实批次。事实批次以修订 ID 为幂等键，网络失败、暂停或服务重启后从最后一个持久检查点继续，不重复抽取已保存的模型结果。

## 保存和恢复

- 任务在后端运行，关闭面板不会停止。暂停在安全检查点生效，当前模型响应会先保存为候选。
- 每个步骤独立保存完整候选、原流程修订、输入、来源指纹、节点缓存和一致性审核。正文使用原确认服务，保留修订历史。
- 正式业务保存和任务检查点在同一个 MongoDB 事务内提交。提交结果不明时，继续任务读取检查点，避免重复创建。
- Agent 的续跑凭证只在所属进程中使用；重启或凭证失效时保留完成节点，明确提示未完成步骤可能重新请求模型。
- 两类自动写作共用书籍租约进行启动准入；同一本书的一键任务和逐卷任务不能同时活动。
- 来源被人工修改时保留候选并停止；结束本轮再重新开始，会从最新正式内容重新判断缺项。已有正文、已确认剧情和参与计划不会自动覆盖。
- 章后事实抽取、每次审核和最终采用都单独保存检查点。普通事实需要一次独立审核；高风险事实需要两次独立审核。无效引文、未知对象、错误章前值或审核阻断最多自动修订两次，仍无法确认时才暂停等待处理。

## 一致性边界

所有自动采用步骤都需要真实的原任务来源材料。正文和剧情继续使用原有按位置资料整理及事实读取；全书设计材料不当作已发生的章节事实。独立审核核对身份、时间地点、状态、知情范围、视角和剧情边界；冲突必须有候选与来源双方逐字引证。

物品会通过原事实批次合同确认在书初，因此审核额外读取实际采用合同：生命周期、持有人、控制势力、地点是书初事实，不是未定位的未来配置。明确后期才创制的物品不能以 available/held 提前确认；引用 null 表示明确无引用，不代表未知。审核引文必须各自来自单个字段的连续原文，不能拼接描述与 JSON 字段以绕过证据校验。

卷骨架原任务读取的是全书设计资料，一键首章流程额外读取其来源人物在 book_start 的实际事实并持久化到审核材料。首卷真实开局必须与已经确认的年龄、身份、伤势与能力相容；回忆不能无说明地将整卷当前状态重置到更早时期。若已有资料本身的开篇时间冲突，不自动覆盖，应先由作者选择统一的时间锚点。

卷势力候选审核与正式采用共用字段投影：仅保存参与计划，不将旧兼容 state 的实力/资源占位值当成事实；新增势力也不从这些占位值合成初始事实。原模型候选完整保留。引证路径同时支持 `.0` 与 `[0]` 的数字数组下标，仅按真实字典/数组查找，绝不执行路径表达式。

明确冲突最多自动修订两次，每次保留被拒候选和引证；仍有冲突则停止。缺失审核材料和无法验证的引证不会静默放行。首章审核记录绑定保存后的正文修订、内容 hash 和生成依据。

自动章后事实使用追加式 `chapter_fact_batches` 账本。每项事实必须指向本次写作实际读取的稳定对象，`before` 必须等于上一章已确认值，证据必须按 Unicode 码点精确匹配固定正文修订。审核可接受、忽略或阻断候选；忽略项只保留在审计记录中，不会进入下一章。下一章只读取剧情位置上可见、且与当前正文版本匹配的已确认批次；作者后来修改前章时，旧批次保留为历史，但系统会阻止继续写作，直到新版本重新核对完成。

本阶段的自动事实账本是后续 AI 写作的权威章间上下文，但不会直接改写现有人物、势力、物品等人工维护的结构化事实表。这样可以避免模型自动覆盖作者资料；需要将账本事实同步到这些工作台时，应另做带字段合同的映射流程。

这是一套基于证据的一致性护栏，不保证 AI 检出所有语义矛盾。当前范围没有跨卷事实演化、全书时间线或长期伏笔闭环，不能据此声称已具备 600 章无人干预连续创作能力。

## 日志

首章任务面板默认显示业务步骤时间线，按执行顺序列出结果保存状态、开始/保存时间和历时；历时包含暂停与重试，不把并行节点时间相加。已保存步骤以事务检查点为准，不因历史失败记录误报最终失败。被替换的未采用步骤单独列入“历史调整”。历史记录反映当时的保存结果，不随后续人工修改或回退而改写。

展开业务步骤后，复用逐卷写作的节点日志查看器，仅加载该步骤的节点、输出及历史错误。输出有长度上限并过滤凭据字段，节点日志可分页。任务不运行时停止节点自动刷新。最近 30 轮任务可切换查看，任务开始与结束时间明确标注；已完成任务隐藏写作要求和重新启动按钮。只读接口按小说、任务、步骤隔离，不触发生成或保存业务内容。

节点原始状态不改写；接口按当前尝试返回活动标记，续跑及自动修订后旧尝试不会再次显示运行。分页缓存也会依据不含凭据的关联摘要刷新活动状态。保存完成日志与业务保存、任务检查点同事务提交，防止提交成功但响应丢失时遗漏成功日志。

连接或响应流提前中断与模型内容格式无效使用不同错误码；不完整的响应不作为候选保存，已完成的资料整理节点仍可复用。

进行中或已中断的节点不展示尚未定稿的耗时，避免把启动事件的零值误显示为“用时 0.00 秒”；已完成和失败节点保留实际耗时。

逐卷日志会显示“提取章后事实”“独立审核章后事实”“修订章后事实候选”和“更新事实库”。展开输出可以查看候选数量、审核决定、修订次数、采用/忽略数量及事实批次 ID；日志不展示或修改正文。

## 验证

在项目根目录运行（需要本机 MongoDB 副本集）：

```powershell
.venv\Scripts\python.exe -m unittest scripts.test_first_chapter scripts.test_first_chapter_runtime scripts.test_first_chapter_flow -v
```

运行测试会创建并清理 `ai_ng_first_chapter_test_*`、`ai_ng_first_chapter_flow_test_*` 临时数据库，不写正式作品。完整流程测试使用固定 AI 响应，实际运行原有任务图、来源校验、确认服务、事务、修订和事实批次；它验证流程正确性，不代表真实模型的写作质量。

前端检查：

```powershell
cd frontend
node_modules\.bin\tsc.cmd --noEmit --allowImportingTsExtensions --pretty false
node_modules\.bin\eslint.cmd src/components/writing/novel-info/FirstChapterWriting.tsx src/components/writing/novel-info/NovelInfoWorkspace.tsx
```
